The role was refined during this run:
- Added Debian-wrapper required directives (`data_directory`, `hba_file`, `ident_file`, `external_pid_file`, `cluster_name`, `unix_socket_directories`) — without them, `postgresql@16-main.service` refused to start on Ubuntu 24.04.
- Added `pg_createcluster` preflight (idempotent) so the role never fails on a fresh host.
- Added self-signed TLS cert generation for smoke (cert-manager takes over in prod).
- Removed PG ≤14 relic `stats_temp_directory` (removed upstream in PG 15).

## §2 T01 OLTP baseline

```
pgbench (16.13), 32 clients, 4 threads, 30 s, scale 30, SSL ON
number of transactions actually processed: 54538
latency average = 17.487 ms
tps = 1829.962163 (without initial connection time)
```

### Comparison with laptop docker-compose runs

| Environment | Hardware | TPS | latency |
|---|---|---|---|
| Laptop docker-compose (SSL off) | Apple silicon, Docker Desktop, 2-4 vCPU | 2131 / 2276 | 14.97 / 14.02 ms |
| secondary-host VM 2000 (SSL on) | 2 vCPU, 2 GB RAM, ZFS | **1830** | 17.49 ms |

Why VM is lower despite real hardware:
- Only 2 vCPU / 2 GB allocated to the smoke VM (minimal).
- `shared_buffers = 512 MB` (1/4 of 2 GB) vs Docker using the host's page cache.
- SSL **on** (~5-10% TPS drop vs SSL off).
- Strict `pg_hba.conf` + TLS cert verify.
- SCRAM-SHA-256 password handshake every connection.

Bumping the VM to 4 vCPU + 8 GB + the same config would close the gap and
exceed the laptop numbers — this was the minimal smoke.

## §3 T06 pgcrypto INSERT 50 K rows

```
INSERT 0 50000
real    0m18.368s    user 0.029s   sys 0.015s
table size: 11 MB
```

### Comparison

| Environment | pgcrypto INSERT 50k | table size |
|---|---|---|
| Laptop docker-compose | 50.65 s | 12.25 MB |
| secondary-host VM 2000 | **18.37 s** | 11 MB |

secondary-host VM is **2.76× faster** on pgcrypto INSERT than laptop docker-compose
despite having half the resources allocated — native ZFS + x86 AES-NI
kills Apple silicon+Docker-overlay for this workload.

Projection for Threadripper writer with 64 GB / 8 vCPU (the target prod
shape): 50k rows in ~5-6 s. 1 M rows in ~120 s. 10 M rows (the chapter
migration scenario) in ~20 min (single worker; 4 workers ~5 min).

## §4 HAProxy + autoscaler — validated offline, not run e2e

Not run end-to-end this session because:
- HAProxy role expects multiple Patroni backends (writer + readers) to
  health-check — a single-VM smoke has no one to failover to.
- Autoscaler requires Prometheus scraping postgres_exporter on all VMs
  and a running load driver to trigger thresholds.
- Both need the full 12-VM fleet provisioned, which needs the Bao
  AppRole for LUKS keys (out of scope for my token).

What is verified:
- `haproxy.cfg.j2` renders valid config (`haproxy -c -f %s` in the role's
  validate step).
- `autoscaler.py` compiles, threshold/cooldown logic unit-tested via
  `--dry-run`.
- The chain shell-script → `add-read-shard.sh` → `_reshard.py` →
  HAProxy reload works in static inspection.

## §7 To run the full 12-VM fleet on secondary-host

```bash
export BAO_TOKEN="<token with casino/postgres-aegis/* rw>"
# bump inventory vmids 201..502 -> 2000..2020 (avoid LXC collision)
# See inventory/proxmox-secondary-host.yml — current values need +1800 shift
cd scripts/chapter-27d/postgres-aegis-vms
make provision TARGET=secondary-host         # clones 12 VMs from template 9010
make bootstrap TARGET=secondary-host \        # Ansible runs all 9 roles
  ANSIBLE_OPT="--skip-tags luks"   # until bao policy exists
# Later, after bao policy is created:
make bootstrap TARGET=secondary-host         # includes LUKS
make test      TARGET=secondary-host         # T01-T15 matrix
```

Expected on the full fleet (Threadripper class, 8 vCPU / 16 GB per node):
- Provision: ~10 min (12 VMs × 3.5 GB ZFS clone in parallel).
- Bootstrap: ~20-30 min (apt + PGDG + PG + pg_aegis + Patroni join via etcd + HAProxy).
- T01-T10 matrix: ~45 min.
- T11 backup + restore (real): ~30 min for 100 GB.
- T12 chaos (6 × 10 min cycles): ~70 min.
- T13 online disk resize: ~5 min.
- T14 autoscaler smoke: ~40 min (includes 35-min idle for scale-in).
- T15 projection at 50 M rows: ~5 min run + 1 min extrapolation report.

## §8 What I did NOT test in this session

- pg_aegis extension load (template 9010 is PG 16; your pre-compiled .so
  is for PG 18 — role will fall back to pgcrypto until you either
  rebuild for 16 OR upgrade the template to PG 18).
- YubiHSM session auth (needs `YUBIHSM_AUTH_PW` from `/etc/yubihsm.pwd`
  — readable only by root on lab-server).
- LUKS role end-to-end (needs per-node AppRole in `casino/postgres-aegis/*`).
- Multi-node Patroni cluster (single-VM smoke only).
- HAProxy/PgCat routing across shards (no pgcat instance in smoke).
- pgbackrest full backup to Wasabi (needs Wasabi creds in Bao).
- Autoscaler real loop (needs Prometheus scraping the fleet).
