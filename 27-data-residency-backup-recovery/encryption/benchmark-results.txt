 3. pgcrypto Column-Level Encryption Overhead
--------------------------------------------------------------------------------
Dataset:           50,000 rows, 3 encrypted columns (email, full_name, ssn)
Encryption:        pgp_sym_encrypt with AES-256, pgp_sym_decrypt on read
Key:               256-bit symmetric (casino-tde-pgcrypto-2024)

                          PLAIN COLUMNS     pgcrypto ENCRYPTED
  ─────────────────────────────────────────────────────────────
  SELECT 10,000 rows:     3.762ms           10,873.379ms
  Per-row read cost:      0.000376µs        1,086.96µs
  Overhead (read):        baseline          +288,000% (288x slower)

  INSERT 1,000 rows:      ~0.5ms est.       1,261.4ms
  Per-row write cost:     ~0.0005ms est.    1.261ms

  10,000 encrypt+decrypt
  cycle benchmark:        N/A               ~12,323ms
  Throughput:             N/A               ~812 ops/sec

BREAKDOWN: pgcrypto uses OpenPGP packet format (RFC 4880) which adds:
  - Session key encryption + integrity MDC per call
  - Base64/binary encoding overhead
  - Random IV generation per encryption
  Net: ~1ms per row for decrypt (3 columns). For 100 concurrent queries
  each touching 100 encrypted rows = 30,000 decrypts/sec needed.
  With 128 cores this is ~234 decrypts/core/sec — feasible for iGaming.

OPTIMIZATION RECOMMENDATIONS:
  a) Cache decrypted results in application layer (Redis/pgBouncer)
  b) Use pgcrypto encrypt_iv() with pre-fetched IVs for batch operations
  c) Consider pg_tde (PostgreSQL 17+) for table-level transparent encryption
     — eliminates per-row decrypt cost entirely
  d) Limit encrypted column queries to specific player lookups, not bulk scans
  e) Use pgcrypto hash + encrypt pattern: hash for lookups, decrypt only on match

--------------------------------------------------------------------------------
 9. Recommendations for Production iGaming
--------------------------------------------------------------------------------

1. LUKS disk encryption: DEPLOY — zero measurable overhead with AES-NI.
   Use AES-XTS-512 (256-bit effective), PBKDF2-SHA512.
   Store LUKS passphrase in HSM (YubiHSM2 or AWS KMS).

2. pgcrypto column encryption: DEPLOY for PAN/PII columns only.
   Overhead is ~1ms/row but acceptable for targeted player lookups.
   Do NOT use for bulk analytics queries on encrypted columns.

3. pg_tde (PostgreSQL 17+): EVALUATE — transparent, ~2% overhead.
   Currently in Percona preview; production-ready in PG 17/18 cycle.

4. Key rotation: AUTOMATE quarterly.
   LUKS slot rotation: <5 seconds.
   Full volume re-encryption (for master key compromise): budget 2-4h/TB.

5. Audit logging: Enable log_statement='ddl', log_connections=on.
   Combine with pgaudit extension for PCI-DSS 10.x compliance.
